## P0: 쇼핑 기능이 실제로 안 되는 문제

### 1. 장바구니·찜 상태를 앱 전체에서 공유하고 저장하기 (M)

- **현재:** "장바구니 담기"를 눌러도 모달만 닫힙니다 (`handleAddCart`). 장바구니는 항상 같은 목업 2개만 보여 줍니다. 상태가 페이지마다 `useState`에만 있어서 페이지를 이동하거나 새로 고치면 초기화됩니다.
- **할 일:** 장바구니 스토어(Context+`useReducer` 또는 Zustand)를 만들고 `localStorage`에 저장합니다. 담기, 수량 변경, 삭제가 모두 이 스토어를 거치게 합니다.
- **이유:** 이게 있어야 2번 이후 작업이 의미가 있어서 가장 먼저 해야 합니다.
- **위치:** `src/pages/shop/ProductView/index.tsx`, `src/pages/cart/index.tsx`, `src/pages/like/`

### 2. 장바구니 로직 버그 고치기 (S)

- 선택 상태를 배열 위치로 관리해서, 항목을 삭제하면 체크 상태와 결제 금액이 어긋납니다 (`selectedProducts.splice(index, 1)`). 상품 ID로 관리하도록 바꿉니다.
- 수량 변경이 원본 목업 객체를 직접 고칩니다 (`updatedData[index].count += 1`). 모듈 전역인 `cartProductData`까지 바뀌므로 새 객체를 만들어서 바꾸도록 합니다.
- "N개 선택상품"의 N이 상품 종류 수가 아니라 수량 합계입니다. 예: 상품 2종(수량 2+1) → "3개".
- 리스트 `key`를 인덱스 대신 상품 ID로 바꿉니다.
- 수량 입력창이 `onChange` 없이 `value`만 지정되어 있어 직접 입력할 수 없습니다. 최대 수량·재고 확인도 없습니다.
- **위치:** `src/pages/cart/index.tsx`

#### 11. 추가 (2026-11-25): 브라우저 E2E·자동 실행

**브라우저 E2E (Playwright 1.49.1, devDependency)**
- 작업 중 임시 스크립트로 돌리던 장바구니·찜·주문·전체 경로 시나리오를 프로젝트 테스트(`e2e/`)로 옮겼습니다.
- 순서대로 이어지던 스크립트를 **서로 독립된 테스트**로 나눴습니다. 각 테스트는 새 브라우저(빈 localStorage)에서 시작합니다.
- **실행 방법**
  - `npm run test:e2e`: 빌드한 뒤 실행
  - `npm run e2e`: 이미 빌드된 `build/`로 실행
  - 처음 한 번은 `npx playwright install chromium`으로 브라우저를 받아야 합니다.
- 프로덕션 빌드를 `scripts/serve-build.js`(의존성 없는 정적 서버, 포트 4173)로 띄워서 테스트합니다 (`playwright.config.ts`의 `webServer`). 화면 크기는 420×900, 모바일입니다.
